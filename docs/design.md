# 設計（design）

外から見た振る舞い（B-nn）と、部品の境目を書く。振る舞いは、ここにだけ書く。事実の根拠は `docs/research.md`（以下 research）の節で指す。3節の表（キーコード・文字・座標・対応表・見本・エラー・直前のキー）は、コードとテストが写す元（正）。

## 0. 用語

- **最初の版**: 最初に公開するまでの範囲。`docs/todo.md` の 1〜4周目に当たる。research が「1周目の範囲」と書いている物と同じ（todo の「1周目」と紛れるので、ここでは「最初の版」と書く）。
- **位置**: Cornix の行列の位置 (行,列)。行0〜3が左手、行4〜7が右手。右手は列0が外側。キーのある位置は 50（48キー＋丸い部品の押し込み2つ）。
- **手元のキー**: 利用者が実際に押す、ふつうのキーボードのキー。ブラウザの `KeyboardEvent.code` の文字列で見分ける。
- **配列**: PC の側のキーボード配列（JIS か US）。キーコードから文字を決めるのに使う。
- **有効なレイヤー**: レイヤー0（いつも有効）と、MO(n) で有効にしているレイヤー。
- **欄**: 出た文字の欄。
- **未対応**: 最初の版では動かさないキーコード。図に出すが、押しても何も出ない。

## 1. 画面の部品

`static/index.html`（シミュレータ本体）。上から順に:

1. 題「Cornix LP シミュレータ」と、断り書き
2. 案内（いま出ているキーマップ、知らせ、読めなかった理由、公式マニュアルへのリンク）
3. 操作の列: 「.vil を選ぶ」／配列（JIS・US）／「手元のキーの名前」のチェック／「全画面で試す」／「キーを全部離す」
4. 注意（B-43）
5. レイヤーの列: 「自動」と番号のボタン、有効なレイヤーの番号
6. 配列の図（48キーと、丸い部品2つ）
7. 修飾キーの札（Shift・Ctrl・Alt・GUI）と、「直前のキー」
8. 欄と、「全部消す」

`static/keytest.html`（計測ページ。2.10節）は、別のページ。

画面の文言は日本語だけ。入力欄（テキストを打ち込む欄）は置かない（置くと、手元のキーの文字がそのまま入り、IME も働くため）。

## 2. 外から見た振る舞い

### 2.1 開いたとき

- **B-01** `index.html` を開くと、1節の部品が出る。最初は、見本のキーマップ（3.5節）が読み込まれた状態で、すぐ打てる。
- **B-02** 最初の案内は「いま出ているのは、見本のキーマップです。Cornix の初期キーマップ（cornix-default-keymap.vil）は、公式マニュアルの「初期キーマップ」から入手して、「.vil を選ぶ」で読み込めます。」と、公式マニュアル（research の S1）へのリンク。
- **B-03** 題の近くに、いつも「非公式（メーカーとは関係のない、個人の制作物）」と出す。
- **B-04** 設定（配列・手元のキーの名前の表示）と、読み込んだ .vil は、ブラウザに覚えない。開き直すと、初期値（見本・JIS・名前を出す・「自動」）に戻る。

### 2.2 .vil の読み込み

- **B-05** 「.vil を選ぶ」でファイルを選ぶと、中身を文字列のまま、ロジックに渡して読む。
- **B-06** 読めたら、図がその .vil の中身に変わる。押されているキー・有効なレイヤー・修飾キーは、はじめの状態（何も押していない）に戻す。表示するレイヤーは「自動」に戻す。欄・「直前のキー」・配列の選択は変えない。
- **B-07** 読めたら、案内を「読み込みました: {ファイル名}（レイヤー {N} 個）」に変え、続けて知らせを出す。知らせは「動かない物: 未対応のキー {a} 個、コンボ {b} 個、タップダンス {c} 個、マクロ {d} 個」で、0 個の物は省く。全部 0 なら、知らせは出さない。数え方は B-10。
- **B-08** 読めないときは、案内に「読めませんでした: {理由}」を出す（理由は 3.6節）。図と状態は、前のまま。
- **B-09** 読み取りの決まり:
  1. 入力は JSON。いちばん外側はオブジェクトで、`layout` を持つ。
  2. `layout` は、レイヤーの配列（1個以上。上限は無い）。レイヤーは、8行の配列。行は、7列の配列。
  3. マスの値は、文字列か整数。
  4. キーのある50の位置（3.3節）では、文字列は 3.1節の表で読む。表に無い文字列は「未対応」になり、元の文字列を保つ。-1 は KC_NO と同じに扱う。-1 以外の整数は「未対応」（表示は10進の数字）。
  5. キーの無い6つの位置（(0,6) (1,6) (3,6) (4,6) (6,6) (7,6)）は、値が文字列か整数であれば、中身は見ない。
  6. `layout` のほかの項目（version・uid・encoder_layout・settings など）は、あっても無くてもよく、値は見ない（B-10 で数える3つを除く）。uid が何であっても読む。
  7. 先頭の BOM（U+FEFF）と、JSON の前後の空白・改行は許す。
  8. 1〜3 に合わないときは、3.6節のエラー。最初に見つけた1つを返す（見る順は、外側から内側へ、レイヤー・行・列の小さい順）。
- **B-10** 知らせの数え方:
  - 未対応のキー: 48キーの位置（50の位置から、丸い部品の (2,6) と (5,6) を除く）について、全レイヤーで「未対応」になったマスの数。
  - コンボ: `combo` が配列のとき、その要素（配列）のうち、文字列の値に "KC_NO" でない物が1つでもある物の数。
  - タップダンス: `tap_dance` について、コンボと同じ数え方（数値の要素は見ない）。
  - マクロ: `macro` が配列のとき、その要素のうち、空でない配列の数。
  - `combo`・`tap_dance`・`macro` が無い、または配列でないときは、0 個（エラーにしない）。

### 2.3 配列の図

- **B-11** 図には、48キーを四角で、丸い部品2つを丸で、3.3節の座標と回転のとおりに描く。
- **B-12** 丸い部品（(2,6) と (5,6)）の中には、いつも「未対応」と書く。何が割り当ててあっても、押せない（手元のキーを当てない）。最初の版では、押し込みも回転も動かさない。
- **B-13** キーの刻印は、表示するレイヤーの選び方（B-18）で決まる。「自動」（初期値）のとき、押されていないキーには、「いま押したら決まるキーコード」（B-25 の決め方）の刻印を出す。押されているキーには、押したときに決まったキーコードの刻印を、ふつうの濃さで出す（離すまで変わらない）。
- **B-14** 「自動」のとき、決まったキーコードが、有効なレイヤーのうち番号がいちばん大きいレイヤーの物でない（KC_TRNS を通って、下のレイヤーから来た）キーは、刻印を薄く出す。KC_NO に決まったキーと、レイヤー0まで KC_TRNS だったキーは、刻印を空にする。
- **B-15** キーコードごとの刻印（種類は 3.1節）:

  | 種類 | 刻印 |
  |---|---|
  | 文字のキー | 下に素の文字、上に Shift 側の文字（選んでいる配列。3.2節）。英字は、大文字1つだけ。Shift 側が「なし」なら、下だけ。素が「なし」なら、3.2節の「名前」 |
  | 欄を変えるキー・名前だけのキー・修飾キー | 3.1節の「名前」 |
  | MO(n) | 「MO(n)」 |
  | Shift 付き | Shift 側の文字1つ（選んでいる配列）。「なし」なら、キーコードの文字列 |
  | KC_NO（と、キーのある位置の -1） | 空 |
  | KC_TRNS | 「自動」のときは B-13・B-14。番号を選んでいるときは「▽」 |
  | 未対応 | キーコードの文字列をそのまま、小さく薄く（-1 以外の整数は、10進の数字） |

- **B-16** 「手元のキーの名前」が入っている間（初期値は入り）、対応表（3.4節）で手元のキーが当たっているキーの隅に、手元のキーの刻印を小さく出す。当たっていないキーには「手元のキー無し」と小さく出す。チェックを外すと、どちらも出さない。
- **B-17** 押されているキーは、色を変えて光らせる（表示するレイヤーが何であっても）。
- **B-18** レイヤーの列には、「自動」と、読み込んだキーマップのレイヤーの番号（0 から）のボタンを出す。番号を選ぶと、図は、そのレイヤーの中身をそのまま出す（KC_TRNS は「▽」、KC_NO は空、そのほかは B-15 の刻印。薄くはしない）。番号を選んでいる間も、打った結果（光る・有効なレイヤー・欄）は変わらない。「自動」を選ぶと、B-13 に戻る。
- **B-19** 「有効なレイヤー: 0・1」の形で、有効なレイヤーの番号を、小さい順に、いつも出す。

### 2.4 打つ

- **B-20** 手元のキーの keydown（repeat の付いていない物）で、対応表（3.4節）から位置を引き、その位置のキーを押した扱いにする。keyup で、離した扱いにする。
- **B-21** 対応表にある手元のキーの keydown と keyup では、ブラウザの既定の動きを止める（preventDefault）。対応表に無いキーには、何もしない（F5 や F12 は、ブラウザの動きのまま）。
- **B-22** 押されている位置を、もう一度押した扱いにはしない（無視する）。押されていない位置を離しても、何も起きない。
- **B-23** 押し続け（repeat の付いた keydown）では、レイヤーと修飾キーの状態は変えない。「直前のキー」も変えない。その位置が、押したときに「欄を変える」キーコード（文字のキー・Shift 付き・欄を変えるキー）に決まっていたら、いまの修飾キーの状態で、欄への動き（B-38）をもう一度する。押されていない位置の押し続けは、無視する。
- **B-24** 次のときは、押されているキーを全部離した扱いにする（有効なレイヤーはレイヤー0だけに、修飾キーは全部切れた状態に戻る。欄と「直前のキー」は変えない）: 窓がフォーカスを失ったとき／ページが隠れたとき／「キーを全部離す」を押したとき／全画面を抜けたとき（B-44）。

### 2.5 レイヤー

Cornix のファームウェア（RMK）の動きに合わせる。根拠は research 3.4節。

- **B-25** キーを押したとき、有効なレイヤーを、番号の大きい方から順に見る。その位置のキーコードが KC_TRNS なら、次に番号の大きい有効なレイヤーを見る（有効でないレイヤーは飛ばす）。KC_TRNS でないキーコードに当たったら、そのキーコードに決まる（KC_NO も、ここで決まる）。レイヤー0も KC_TRNS だったときは、「割り当てなし」に決まる。
- **B-26** KC_NO と「割り当てなし」に決まったキーは、押しても離しても、何も起きない（「直前のキー」は「（割り当てなし）」になる）。
- **B-27** 決まったキーコードは、その位置を離すまで覚えておく。離したときは、覚えたキーコードで処理する（押している間に、有効なレイヤーが変わっても同じ）。
- **B-28** レイヤー0は、いつも有効。MO(n) に決まったキーを押すと、レイヤー n が有効になり、離すと無効になる。
- **B-29** MO を2つ押している間は、両方のレイヤーが有効で、B-25 のとおり、番号の大きい方から見る。
- **B-30** レイヤーの有効・無効は、レイヤーごとに1つだけ持つ（押している数は数えない）。同じレイヤーの MO を2つ押して1つ離すと、もう1つを押したままでも、そのレイヤーは無効になる。
- **B-31** MO(n) の n がレイヤーの数以上のときは、押しても離しても、何も起きない（刻印は MO(n) のまま）。MO(0) は、レイヤー0がいつも有効なので、見た目は変わらない。

### 2.6 修飾キーと、Shift 付きのキーコード

- **B-32** 修飾キー（3.1節の8つ）に決まったキーを押すと、その修飾が入り、離すと切れる。札（Shift・Ctrl・Alt・GUI）は、左右のどちらかが入っていれば点く。
- **B-33** 修飾の入・切は、8つそれぞれに1つだけ持つ（押している数は数えない）。同じ修飾キー（例: KC_LSHIFT）を2つ押して1つ離すと、その修飾は切れる。左と右は、別々に持つ。
- **B-34** Shift 付きのキーコードは、その処理の間だけ Shift が入っている扱いで、中のキーを処理する。札は変えない。
- **B-35** Ctrl・Alt・GUI のどれかが入っている間は、どのキーを押しても、欄は変えない（「直前のキー」に、組み合わせが出る）。

### 2.7 文字への変換

- **B-36** 配列は JIS と US。初期値は JIS。画面で切り替えると、刻印（B-15）と、そのあとに出る文字が変わる。欄にすでに出た文字と、押されているキー・レイヤー・修飾キーの状態は変わらない。
- **B-37** 文字のキーは、3.2節の表で文字に変える。Shift（左右のどちらか、または Shift 付きのキーコード）が入っていれば Shift 側、そうでなければ素。CapsLock の状態は持たない（KC_CAPSLOCK は、名前だけのキー）。

### 2.8 欄と、直前のキー

- **B-38** 欄は、末尾に足すだけの表示（カーソルは無い）。Ctrl・Alt・GUI がどれも入っていないとき:
  - 文字のキー（Shift 付きを含む）で、表に文字がある → その文字を末尾に足す。「なし」→ 欄は変えない。
  - KC_SPACE → 空白を足す。KC_ENTER → 改行を足す。KC_TAB → タブ文字を足す。
  - KC_BSPACE → 末尾の1文字を消す（欄が空なら、何もしない）。
- **B-39** そのほかのキー（名前だけのキー・修飾キー・MO・未対応・KC_NO）は、欄を変えない。
- **B-40** 「全部消す」を押すと、欄と「直前のキー」が空になる。キー・レイヤー・修飾キーの状態は変わらない。
- **B-41** 「直前のキー」は、キーを押す（押し続けを除く）たびに書き換える1行。形は 3.7節。

### 2.9 全画面と、先に取られるキー

根拠は research 4.3節。

- **B-42** 「全画面で試す」を押すと、ページを全画面にして（`requestFullscreen`）、Keyboard Lock を掛ける（`navigator.keyboard.lock()`）。ボタンは「全画面をやめる」に変わり、押すと元に戻る。Keyboard Lock が無いブラウザでも、全画面にはする。
- **B-43** 注意の文は、状態で変わる:
  - ふつうの窓: 「ふつうの窓では、Ctrl+W でタブが閉じ、Win キーでスタートメニューが開きます。Ctrl・Win・Alt も試すときは「全画面で試す」を使ってください。」
  - 全画面で、Keyboard Lock が掛かっている: 「全画面です。Esc の長押し（2秒）で戻ります。」
  - 全画面で、Keyboard Lock が掛けられなかった（ブラウザが対応していない・許可されなかった）: 「全画面ですが、このブラウザでは Win キーなどを受けられません。」
- **B-44** 全画面を抜けたとき（Esc の長押し・ボタン・そのほか、どの抜け方でも）、Keyboard Lock を外し、押されているキーを全部離した扱いにする（B-24）。
- **B-45** 対象のブラウザは、Windows の Chrome と Edge。ほかのブラウザは確かめない（README に書く）。

### 2.10 計測ページ（keytest）

手元のキーが、ブラウザにどう届くかを見るページ。1周目の実測（`docs/measurements.md`）に使い、そのあとも残す（キーボードや常駐ソフトを変えたときに、測り直すため）。

- **B-46** `keytest.html` を開くと、題・説明・操作（「preventDefault する」のチェック、「全画面＋Keyboard Lock」、「記録を消す」）・まとめの表・直近のイベントが出る。
- **B-47** まとめの表は、キーを押す・離すたびに、code ごとの行を書き換える。列は、code／key（届いた値を、届いた順に、重複なしで並べる）／location／keydown の回数（repeat を除く）／keyup の回数／repeat の回数。行は、最初に届いた順。code が空文字のときは、code の欄を「（空）」とし、key の値ごとに別の行にする。
- **B-48** 直近のイベントは、新しい順に20件。種類（keydown・keyup）／code／key／repeat。
- **B-49** 「preventDefault する」が入っている間（初期値は入り）、全部の keydown と keyup で、既定の動きを止める。外すと、止めない。
- **B-50** 「全画面＋Keyboard Lock」は、B-42 と同じ動き。Keyboard Lock が掛かったか、掛けられなかったかを、ページに出す。
- **B-51** 「記録を消す」で、まとめの表と直近のイベントが空になる。
- **B-52** まとめの表と同じ中身を、Markdown の表の文字として、ページの下にも出す（マウスで選んでコピーし、`docs/measurements.md` に貼るため）。

## 3. 表（正）

### 3.1 キーコードの表

.vil のキーコードは文字列。名前は、.vil という書式の語彙として使う（えだの決定。5節の Q-11）。表は、ここに自分で書いた物で、vial-gui・QMK のファイルは写していない。番号は USB HID の番号（参考。最初の版のコードでは使わない）。大文字と小文字は区別する。前後に空白のある文字列と、別名（KC_BSPC・KC_TRANSPARENT など。vial-gui は .vil に書かない。research 3.5節）は、未対応。

| 文字のキー | KC_A〜KC_Z（0x04〜0x1D）、KC_1〜KC_9（0x1E〜0x26）、KC_0（0x27）、KC_MINUS（0x2D）、KC_EQUAL（0x2E）、KC_LBRACKET（0x2F）、KC_RBRACKET（0x30）、KC_BSLASH（0x31）、KC_NONUS_HASH（0x32）、KC_SCOLON（0x33）、KC_QUOTE（0x34）、KC_GRAVE（0x35）、KC_COMMA（0x36）、KC_DOT（0x37）、KC_SLASH（0x38）、KC_RO（0x87）、KC_JYEN（0x89） |

### 3.3 座標の表

- **出どころ**: 公式ファームウェア V1.12（research の S8。V1.12.zip の SHA-256 は ef5f1205…）の左手側のファイル（cornix-left.uf2）に埋め込まれた、Vial 用の機種定義（xz で圧縮。展開すると 2,149 バイト、SHA-256 は 9a86b3a744c889295e97c7d4671c3f7aae4573dcdd874e0891ea2495332605fb）。この数値を使うことは、えだが決めた（2026-10-03。5節の Q-10）。**メーカーの許可は未確認**。cornix-studio のファイルからは写していない。

### 3.7 「直前のキー」の形

キーを押したとき（押し続けを除く）に出す文。

| 決まったキーコード | 出す文 | 例 |
|---|---|---|
| 文字のキー（Shift 付きを含む）で、欄に文字を足した | `組み合わせ → 足した文字` | `Q → q`、`Shift+1 → !` |
| 文字のキー（Shift 付きを含む）で、欄を変えなかった（文字が「なし」、または Ctrl・Alt・GUI が入っている） | `組み合わせ` | `Ctrl+C`、`Shift+0`、`半角/全角` |
| 欄を変えるキー・名前だけのキー | `組み合わせ` | `Enter`、`Shift+Tab`、`Esc`、`Ctrl+←` |
| 修飾キー | 入っている修飾（押したあとの状態）を、＋でつないだ物 | `Shift`、`Ctrl+Shift` |
| MO(n) | `MO(n)` | `MO(1)` |
| 未対応 | `キーコードの文字列（未対応）` | `USER00（未対応）` |
| KC_NO・割り当てなし | `（割り当てなし）` | |

- 組み合わせ ＝ 入っている修飾を、Ctrl・Shift・Alt・GUI の順に「+」でつなぎ、最後に「キーの名前」を付けた物。左右は区別しない。Shift 付きのキーコードは、修飾に Shift を足して、中のキーの名前を使う。
- キーの名前 ＝ 英字は、大文字1つ。ほかの文字のキーは、素の文字（選んでいる配列。素が「なし」なら 3.2節の名前）。欄を変えるキー・名前だけのキーは、3.1節の名前。
- 例（見本のキーマップ。配列は JIS）:

```text
押し方                                         直前のキー         欄に足す
(0,1)                                          Q → q              q
(2,0) を押したまま (0,1)                       Shift+Q → Q        Q
(7,3) を押したまま (0,1)                       1 → 1              1
(2,0) と (7,3) を押したまま (0,1)              Shift+1 → !        !
(2,0) と (7,3) を押したまま (4,1)              Shift+0            （なし）
(7,3) を押したまま (0,0)                       半角/全角          （なし）
(3,0) を押したまま (2,3)                       Ctrl+C             （なし）
(3,0) と (2,0) を押したまま (2,3)              Ctrl+Shift+C       （なし）
(3,0) を押したまま (7,5)                       Ctrl+Enter         （なし）
(1,0)                                          Esc                （なし）
(2,0) を押したまま (0,0)                       Shift+Tab          タブ文字
(2,0)                                          Shift              （なし）
(3,0) を押したまま (2,0)                       Ctrl+Shift         （なし）
(7,3)                                          MO(1)              （なし）
```

- 同じ見本で、配列を US にしたとき: (3,3) を押したまま (6,1) は `Shift+- → _`（欄に _）。(3,3) を押したまま (6,0) は `Shift+Ro`（欄は変えない）。(7,3) を押したまま (0,0) は `` ` → ` ``（欄に `` ` ``）。

## 4. 部品の境目

crate は2つ（D-7）。ルートの `Cargo.toml` は `[workspace]` だけにする。

| crate | 中身 | 依存してよい物 |
|---|---|---|
| `cornix_logic` | 判断する部品の全部。ブラウザなしで動き、`cargo test` で確かめる | serde_json だけ。wasm-bindgen・web-sys には依存しない |
| `cornix_web` | 画面（WASM）。DOM との受け渡しだけ。判断は置かない | `cornix_logic`。wasm-bindgen・web-sys・js-sys（target が wasm32 のときだけ） |

`cornix_web` は、マインスイーパー2号機と同じ形にする（`crate-type = ["cdylib", "rlib"]`。画面のコードは `#[cfg(target_arch = "wasm32")]` のモジュール）。ふつうのターゲットでも `cargo test --workspace` が通る（research 5.1節）。

| モジュール | 受ける物 | 返す物 | 決まり |
|---|---|---|---|
| `cornix_logic::keycode` | キーコードの文字列（か整数） | キーコード（種類と中身。未対応は、元の文字列を保つ）。読めない入力は無い（全部、どれかの種類になる） | 3.1節 |
| `cornix_logic::vil` | .vil の中身（文字列） | キーマップ（レイヤー × 8 × 7 のキーコードと、知らせの数）か、`VilError` | B-09・B-10・3.6節 |
| `cornix_logic::sample` | なし | 見本の .vil の文字列（`assets/sample.vil` を埋め込む） | 3.5節 |
| `cornix_logic::chars` | 文字のキー、Shift の有無、配列 | 文字（無いこともある） | 3.2節 |
| `cornix_logic::engine` | キーマップ、位置ごとの「押す・押し続け・離す・全部離す」、配列 | 欄への動き（文字を足す・1文字消す・なし）、「直前のキー」の文。いまの状態（有効なレイヤー・修飾キー・位置ごとに覚えたキーコード）と、「いま押したら決まるキーコード」を、外から読める | B-22〜B-35・B-38・B-39・3.7節 |
| `cornix_logic::text` | 欄への動き、全部消す | 欄の文字列 | B-38・B-40 |
| `cornix_logic::hostmap` | 手元のキーの code（文字列） | 位置（無いこともある）。位置から、手元の刻印も引ける | 3.4節 |
| `cornix_logic::geometry` | なし | 50の位置の座標・回転と、キーか丸い部品かの別 | 3.3節 |
| `cornix_logic::view` | `engine` の状態、配列、表示するレイヤー（自動か番号）、手元のキーの名前を出すか | 位置ごとの「図に出す中身」（下の文字・上の文字・濃さ（ふつう・薄い・未対応・空）・押されているか・手元の刻印）と、有効なレイヤーの番号 | B-12〜B-19 |
| `cornix_web::app`（wasm32 のときだけ） | ブラウザの出来事（keydown・keyup・blur・ファイルの選択・ボタン） | DOM の書き換え | B-01〜B-08・B-11・B-17・B-20・B-21・B-24・B-42〜B-45 |
| `cornix_web::keytest`（wasm32 のときだけ） | ブラウザの keydown・keyup | 計測ページの表。表を作る部分（イベントの並び → 行の並び）は、web-sys を使わない関数に分けて、`cargo test` で確かめる | B-46〜B-52 |

- モジュールと型・関数の名前は目安。実装の項目で決めてよい。「受ける物」と「返す物」の線は変えない。
- 出来事の流れ（打ったとき）: ブラウザの keydown → `app` が code を `hostmap` に渡して位置を得る → `engine` の「押す」→ 返ってきた欄への動きを `text` に当てる → `view` で図に出す中身を作る → `app` が DOM を書き換える。
- 修飾キーとレイヤーの状態は、`engine` が、Cornix の側で決まったキーコードから持つ。ブラウザの `event.shiftKey` などは使わない（手元の Shift が、Cornix では別のキーのことがあるため）。
- ボタンを押したあとは、フォーカスをボタンから外す（手元の Space や Enter で、ボタンが押されないように）。
- 図の描き方（SVG か DOM か、色、大きさ）は、`cornix_web` の実装で決めてよい。3.3節の座標と回転、B-11〜B-19 の中身は守る。

## 7. 最初の版の範囲の外と、あとの候補

範囲の外（D-11。図には「未対応」と出し、押しても何も出ない）:

- 長押しと短押しで役割が変わるキー（LT・MT など）、MO 以外のレイヤー切り替え（TG・TO・DF・OSL・TT など）、ワンショットの修飾（OSM）
- コンボ、タップダンス、マクロ、キーの上書き（key_override）
- Bluetooth の切り替えなど（USERnn）、マウスと音量のキー、丸い部品（押し込みと回転）
- 修飾つきのキーコードのうち、Shift 以外（LCTL(kc) など）
- 練習文と計測、日本語入力（IME）、CapsLock の状態

あとの候補（決まっていない。順番も未定。足すときは、えだが決めて、周を足す）:

- 読み込んだ .vil と設定を、ブラウザに覚える（Q-1 の c）
- 対応表を、画面で変える（Q-6 の 2）
- ページの中で、キーの割り当てを変える。.vil を書き出す（Q-14 の b）
- LT・MT・TG などを動かす
- 丸い部品を、画面のクリックで動かす
