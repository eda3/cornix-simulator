# テスト項目

テストで確かめる中身の置き場です。本体のプロンプトも点検役（test-reviewer）も、このファイルを読みます。項目を変えるのは、えだが決めたときだけです。

- 各項目の中身は `docs/design.md`（以下 design）の番号で指します（B-nn＝振る舞い、3.n節＝表）。表の値が、そのままテストの入力と期待値です。
- 「自動」は `cargo test --workspace` で回るテスト。「ブラウザで見る」は、えだが手元のブラウザで見て確かめる項目（どう見えたら合格かまで書いてあります。結果は `docs/measurements.md` に書きます）。「実測」は、えだが計測ページで測って `docs/measurements.md` に書くこと。
- 自動テストの名前には、項目の番号を入れます（例: `item6_...`）。

## 自動テストの書き方（点検役は、ここを見て「弱い」を判定する）

- 期待値は、design の表から手で写す。実装の関数で期待値を作らない（文字の表・座標の表・対応表・「直前のキー」の文・見本で決まるキーコード）
- 境界を必ず入れる（-1 の位置、いちばん上といちばん下のレイヤー、知らないキーコード、空の入力、MO(0)・MO(31)・MO(32)、レイヤーの数ちょうどの MO）
- 外の物（ブラウザのキーイベント・ファイルの読み込み）は、値を直接渡す形に置き換える（code の文字列、.vil の文字列）
- ふだんのテストは、リポジトリに置いた自作の .vil（`cornix_logic/assets/sample.vil`。design 3.5節の全文）と、テストの中で組み立てた小さな .vil で回す。公式の .vil を使うテストは、`local/cornix-default-keymap.vil` があるときだけ回る形にする（無いときは、何もせずに通る）
- 配列で結果が分かれる物は、JIS と US の両方で確かめる
- テスト用の .vil を組み立てる手伝いの関数（位置とキーコードを渡すと、.vil の文字列を返す物）は、入力を作るのに使ってよい。期待値を作るのには使わない
- 点検の指摘は、実装を1か所わざと壊して、テストが落ちることで確かめる（落ちなければ、そのテストは弱い）

⑥ `engine` レイヤーと、修飾キーの状態（B-25〜B-33。D-12）

確かめるのは、決まったキーコード・有効なレイヤー・修飾キーの入り切り（欄と「直前のキー」は⑦）。

- 見本で、design 3.5節の「有効なレイヤーごとに決まるキーコードの例」の表の全部の行（有効なレイヤーが 0・1／0・2／0・1・2 の3通り。実際に MO を押して、その状態にする）

- 場面2（KC_TRNS と KC_NO の違い）: 「(2,0) → (3,3) → (0,1)」で、(0,1) は KC_1 に決まり、Shift が入っている。「(3,3) → (7,0) → (0,1)」で、(7,0) は KC_NO に決まり、Shift は入っていない。「(3,3) → (2,0) → (0,1)」で、(2,0) は KC_LSHIFT に決まり、Shift が入っている

- 同じレイヤーの MO を2つ（B-30）: レイヤー0の2つの位置に MO(1) を置いた .vil で、両方を押して片方を離すと、レイヤー1は無効になる

- 手元の Q を押している間だけ、図の Q が光る
- `abc` と打つと、欄に `abc`。Bksp に当たるキーで1文字消える。Enter に当たるキーで改行
- MO(1) に当たるキーを押している間、上の段が数字になり、「有効なレイヤー: 0・1」。Q の位置を押すと `1`。離すと、元に戻る（MO(1) の位置は、押している間も `MO(1)` と出ていて、離すとレイヤー0に戻る）
- 左 Shift を押しながら A → 欄に `A`、Shift の札が点き、「直前のキー」が `Shift+A → A`
- Ctrl に当たるキーを押しながら C → 欄は変わらず、「直前のキー」が `Ctrl+C`（Ctrl+W は、ふつうの窓では試さない）
- A を押し続けると、`a` が続けて出る
- キーを押したまま、別の窓をクリックして戻ると、光っているキーが無く、「有効なレイヤー: 0」
- 「キーを全部離す」と「全部消す」が、書いてあるとおりに働く

⑯ .vil を選ぶ（B-05〜B-08）。合格は、次の全部
- `local/cornix-default-keymap.vil` を選ぶと、図が変わり、案内が「読み込みました: cornix-default-keymap.vil（レイヤー 10 個）」と「動かない物: 未対応のキー 6 個」になる
- レイヤー2のボタンを選ぶと、左端の列に USER00・USER01・USER02 が、小さく薄く出る
- .vil でないファイル（README.md など）を選ぶと、「読めませんでした: JSON として読めません」と出て、図は前のまま
- キーを押したまま（マウスで）別の .vil を選び直すと、光っているキーが無い。欄は残っている

⑰ 切り替え（B-15・B-16・B-18・B-19・B-36）。合格は、次の全部（見本のキーマップで）
- 配列を US にすると、右上の端の刻印が `@` から `[` に変わり、押すと `[` が出る。JIS に戻すと `@` が出る。欄にすでに出た文字は変わらない
- 「手元のキーの名前」を外すと、隅の名前が消える。入れると、戻る
- レイヤー1のボタンを選ぶと、上の段が数字になり、KC_TRNS のキーに `▽` が出る。その間も、Q を押すと `q` が出る。「自動」で、元に戻る

⑱ 全画面（B-42〜B-45）。合格は、次の全部
- ふつうの窓のとき、B-43 の注意の文が出ている
- 「全画面で試す」を押すと、（初回は許可の確認のあと）全画面になり、注意の文が「全画面です。Esc の長押し（2秒）で戻ります。」になる
- 全画面の間、手元の Win キーを押すと、スタートメニューが開かず、GUI に当たるキーが光る。Ctrl に当たるキーを押しながら W を押すと、タブが閉じず、「直前のキー」が `Ctrl+W`
- Esc の長押しで、ふつうの窓に戻る。戻ったとき、光っているキーが無い
